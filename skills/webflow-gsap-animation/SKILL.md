# Webflow GSAP 애니메이션 작업 가이드

Timothy Ricks의 "Building Webflow Animations With AI" 라이브(2026-10-09)에서 다룬 접근법을 바탕으로 한 작업 원칙.
레이아웃·클래스·반응형은 `lumos-skill`이 담당하고, 이 스킬은 **애니메이션 코드 작성**만 다룬다. 두 스킬이 충돌하면 클래스 네이밍·스크립트 작성 규칙은 lumos-skill을 따른다.

## 0. 작업 전 필수 확인 (추측 금지)
코드를 쓰기 전에 아래를 확인한다. 모르면 추측하지 말고 사용자에게 묻거나 Webflow MCP로 조회한다.
- 대상 요소의 **실제 클래스명과 부모-자식 DOM 구조**
- 이미 사용 중인 라이브러리와 로드 위치 (GSAP, ScrollTrigger, SplitText 등) — 사이트 설정의 GSAP 옵션, 사이트/페이지 커스텀 코드를 모두 확인
- 해당 요소에 **Webflow Interactions(IX2/IX3)가 이미 걸려 있는지**
- 해당 요소가 **Lumos `data-trigger`/`data-state` 또는 `.is-active` 상태 변수**를 쓰고 있는지
- 모바일/태블릿에서 동작을 다르게 해야 하는지

## 1. 구조 원칙
- 클래스명보다 **`data-*` 속성**으로 타겟팅해 재사용 가능한 모듈로 작성한다. (예: `[data-magnetic]`, `[data-reveal]`)
- 요소가 없으면 조용히 종료한다. (`if (!el) return;`) 페이지마다 없는 요소가 많다.
- 코드는 DOM 로드 후 실행되도록 감싸고, Lumos 방식의 컴포넌트 단위 init guard(`dataset.scriptInitialized`)를 쓴다.
- 한 번에 완성하려 하지 말고 단계적으로 만든다: ① 기본 상태/애니메이션 ② 스크롤·마우스 이벤트 연결 ③ 리사이즈·정리·충돌 방지.

## 2. 스크립트 위치 규칙 (Lumos와 통일)
| 대상 | 위치 |
|---|---|
| 라이브러리(GSAP, ScrollTrigger 등) | 사이트 설정의 GSAP 옵션이 있으면 그것을 우선 사용. 없으면 사이트 Head 커스텀 코드에 CDN 1회만 로드 |
| 컴포넌트 단위 짧은 스크립트 | Lumos 규칙대로 컴포넌트 `_wrap`의 **마지막 자식** `<script>` |
| 여러 섹션을 묶는 긴 시퀀스(페이지 전용) | 해당 페이지 Footer 커스텀 코드(`</body>` 앞) |
| 사이트 공통 모듈 | 사이트 Footer 커스텀 코드 |

같은 코드를 두 곳에 중복으로 넣지 않는다.

## 3. Webflow MCP로 넣을 때의 제약
- `register_inline_script`는 **최대 2000자**. 그보다 길면 `set_page_freeform_code` / `set_site_freeform_code`(Head·Footer 블록 전체 교체 방식)를 쓴다.
- freeform 코드는 블록 **전체를 덮어쓴다**. 쓰기 전에 반드시 기존 내용을 읽고 합쳐서 넣는다.
- MCP의 인터랙션 도구(`data_interactions_tool`)는 **IX3**를 다룬다. GSAP 코드와 같은 요소·속성을 건드리지 않게 한다.
- 변수 값에 수식(clamp, calc, color-mix)을 넣는 것은 MCP에서 실패한 이력이 있다. 애니메이션에 필요한 값은 CSS 변수를 읽어 쓰고, 새 수식 변수는 Designer에서 직접 만든다.
- 퍼블리시·실기기 동작은 MCP로 확인할 수 없다. 확인하지 못한 항목은 산출물에 명시한다.

## 4. GSAP 사용 원칙
- 반응형 분기와 정리는 `gsap.matchMedia()` 또는 `gsap.context()`로 묶는다.
- 마우스 추적처럼 잦은 갱신은 `gsap.quickTo`를 쓴다.
- ScrollTrigger는 리사이즈/레이아웃 변경 후 `ScrollTrigger.refresh()`가 필요한지 점검한다. 이미지·**웹폰트**(`document.fonts.ready`) 로딩 이후 위치가 틀어지는 경우가 많다.
- 스크롤 연동 `scrub`은 값 없이 즉각 반응시키기보다 부드럽게 따라오게 조정하는 것을 기본으로 검토한다. (구체 값은 화면에서 확인해 정한다.)
- 3D 틸트류는 부모에 `perspective`를 주고 회전 한계값을 반드시 제한한다.
- 터치 기기에서는 hover/커서 효과를 끈다.
- `prefers-reduced-motion` 사용자를 위한 대체 처리를 넣는다. (스크롤 시퀀스는 최종 상태를 바로 보여준다.)
- 색상은 hex를 쓰지 않고 Lumos 테마 변수(`--_theme---*`)를 읽어 쓴다.

## 5. IX2/IX3 · Lumos 상태 변수와의 충돌 방지
같은 요소의 같은 속성(`transform`, `opacity`)을 두 시스템이 동시에 제어하면 깜빡임이 생긴다.
- **역할 분리**: 바깥 래퍼는 IX/Lumos trigger, 안쪽 요소는 GSAP (또는 반대)
- Lumos 호버(`data-trigger` + `--_trigger---on`)가 걸린 요소에는 GSAP 호버를 겹치지 않는다.
- JS 상태 토글은 Lumos 규칙대로 `.is-active`만 쓴다.
- 또는 CSS 변수를 매개로 한쪽이 변수를 바꾸고 다른 쪽이 읽게 한다.
- 새 애니메이션을 넣기 전에 해당 요소의 기존 인터랙션을 먼저 확인한다.

## 6. 디버깅 절차
1. 브라우저 콘솔 에러 **전문**을 확인한다.
2. `Cannot read properties of null` 류는 클래스명 오타, 요소 부재, 스크립트 실행 순서 문제를 먼저 의심한다.
3. 수정은 원인 하나씩. 고친 뒤 데스크톱/태블릿/모바일에서 각각 확인한다.

## 7. 산출물 형식
- 붙여넣을 위치를 명시한다 (2번 표 기준).
- 사용한 속성·클래스 목록을 코드 위에 주석으로 적어, 사용자가 Webflow에서 무엇을 설정해야 하는지 알게 한다.
- 검증하지 못한 부분(실제 퍼블리시 확인 등)은 숨기지 않고 명시한다.

- Webflow 사이트: `글로벙컴퍼니` (`6ac8f703fef5e75c9add8463`), Lumos 기반, **기본 테마 = 다크(네이비·금색)**
- 제목 서체 Noto Serif KR(연결 예정) → ScrollTrigger 위치 계산은 `document.fonts.ready` 이후 `refresh()`
- **메인 스크롤 연출 6단계** (PC·모바일 모두, 스크롤 연동):
  1. 우주 공간의 지구 + 사훈 타이틀(글자 순차 등장)
  2. 지구 아래 금빛 광원 확산
  3. 빛을 따라 싹 → 나무·풀·꽃 성장 (스크롤 진행에 따라 보이게)
  4. 중앙 대표 등장
  5. 좌측 조담인, 우측 이철희 등장 (화면 기준 좌·우 고정)
  6. 나머지 구성원 등장 → 한 팀 완성 후 아래 섹션으로 스크롤 이어짐
  - 인물 구도(중앙 대표 슈트, 좌 조담인, 우 이철희)는 고객 확정 사항이므로 변경 금지
  - reduced-motion·저사양에서는 6단계 최종 장면을 바로 표시
- **모바일 하단 고정 '크리에이터 지원하기' 버튼**: 지원(Contact) 페이지 제외 모든 모바일 페이지. 스크롤 연출 중에도 보이고 본문·푸터를 가리지 않게 한다.
- 'LIVE', 시청자 수 등 실시간처럼 보이는 연출은 넣지 않는다 (고객 요청으로 제외).
- 지원서 전환 이벤트·GA4는 애니메이션 코드에 섞지 않으며, 개인정보를 이벤트 값으로 보내지 않는다.
